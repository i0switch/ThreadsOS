# /delegate-check — ハイブリッド委譲判定スキル（Codex + Gemini）

ユーザーのプロンプトを受け取ったら、コードに触る前にこの判定を実行する。

## Step 0: 論点の抽出
ユーザーの発言からすべての作業項目を列挙する。
- 「ついでに」「あと」「それと」の後に続く指示も独立した項目として扱う
- 省略・統合・要約はしない。3つ言ったら3つ出す
- 感情表現（怒り、皮肉、強調）は論点の優先度と重大度の手がかりとして扱う。無視するな

## Step 1: 各項目を委譲条件に照合

以下のいずれかに該当 → **Codex行き**:
- 触るファイルが5つ以上（推定含む）
- リポジトリ全体を読む・探す必要がある
- 同じ操作の繰り返し
- 広範囲のレビュー
- 機械的な変換・整形

以下のいずれかに該当 → **Gemini行き**:
- ウェブ検索・最新情報の調査が必要
- 長文ドキュメントの要約・分析
- API仕様・外部サービスの調査
- ベストプラクティス・技術トレンドの調査
- 公式ドキュメントの確認・比較

以下に該当 → **自分でやる**:
- プロダクト・設計の判断が必要
- ユーザーとの対話・仕様確認が必要
- セキュリティ・認証・機密情報を扱う
- 1〜2ファイルの小さな修正

混在する場合 → 項目ごとに分けて判定する。Codex/Gemini/自分を項目単位で振り分ける。
Codex + Gemini が同時に必要な場合 → 並列で投げる。

### 条件が競合したときのルール
「自分でやる」条件と「Codex/Gemini行き」条件が同時に当てはまる場合 → **委譲を優先する**。

典型的な罠:
- 「1〜2ファイルだから自分で」× 「19箇所の繰り返し修正」→ **Codex行き**が正解
- 判断基準は**ファイル数ではなく作業の性質**。1ファイルでも繰り返し・機械的ならCodex行き
- 「小さな修正」とは作業量が小さいことであって、ファイル数が少ないことではない

### 繰り返しの早期検知ルール
- **同じ種類の操作を2回やったら立ち止まれ**。3回目からはCodexに投げる
- 試行錯誤ループ（実行→確認→調整）が回り始めたら、**調整部分だけCodexに切り出す**
- 「もう1回だけ自分で…」は危険信号。そう思った時点で委譲を検討する

## Step 2: 判定結果を宣言
以下のフォーマットで出力してからタスクに着手する:

**Codex行きの場合:**
```
📦 委譲判定: Codex
理由: {該当条件}
タスク: {委譲内容の要約}
```
→ 即 codex-delegate.ps1 を実行:
```powershell
& "C:\Users\i0swi\OneDrive\デスクトップ\claude.alibaba\scripts\codex-delegate.ps1" `
    -Task "タスク内容" `
    -Mode {research|implement|review|refactor|testfix} `
    -Targets @("対象パス") `
    -Constraints @("制約")
```

**Gemini行きの場合:**
```
🔍 委譲判定: Gemini
理由: {該当条件}
タスク: {委譲内容の要約}
```
→ 即 gemini-delegate.ps1 を実行:
```powershell
& "C:\Users\i0swi\OneDrive\デスクトップ\claude.alibaba\scripts\gemini-delegate.ps1" `
    -Task "タスク内容" `
    -Mode {research|implement|review|refactor|testfix} `
    -Targets @("対象パス") `
    -Constraints @("制約")
```

**並列（Codex + Gemini）の場合:**
```
🔀 委譲判定: 並列（Codex + Gemini）
Codex: {タスク}
Gemini: {タスク}
```
→ 両方のスクリプトを同時に実行する

**自分でやる場合:**
```
🔧 委譲判定: 自分
理由: {該当条件}
```
→ そのまま作業開始

## 禁止事項
- 判定をスキップしてコードに触ること
- 「たぶん自分でやった方が早い」という主観的判断で委譲を回避すること
- 判定結果を出力せずに作業を始めること
- Codex/Gemini行きと判定した項目を自分で処理すること
